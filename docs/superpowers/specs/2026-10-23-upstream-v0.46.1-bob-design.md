# Reapply Bob support on v0.46.1

## Context

The latest tag on the GitHub remote is `v0.46.1`. The current `main` branch
contains Bob parsing work, but the tag has no Bob provider. The two trees differ
in 2,418 files, and this checkout is shallow, so merging the entire internal
branch would risk carrying old code over newer upstream code.

The requested scope is Bob-specific work only. Keep the existing `main`
checkout, its untracked helper, and its ignored build and screenshot outputs
unchanged. Do not push code or generated assets.

## Design

Create a local `upstream-v0.46.1-bob` branch and worktree from the verified
`v0.46.1` tag. Port the Bob provider selectively from the current checkout and
adapt it to the target tag's parser interfaces; do not replay the old v0.44
snapshot commit or merge the rest of the fork.

The port includes:

- Bob JSON session discovery under `.bob/tmp/**/chats/` and read-only SQLite task
  discovery from `.bob/db/bob.db`.
- `AgentBob` registration, provider factory, and migration classification.
  Preserve `.bob` as the default root; `BOB_DIR` and `bob_dirs` override it.
- Existing project resolution behavior: use the task directory when present,
  then `env.workspace`, then a `file:` project identifier. Preserve context
  propagation through SQLite lookups.
- Tests for default roots and overrides, JSON and SQLite sessions, legacy task
  directories, project lookup, usage fields, and SQLite sidecar changes.
- A Session Discovery row in `docs/configuration.md`, a focused Unreleased
  changelog entry, and the Bob format-provenance entry. Recheck the format
  evidence and document `.bob` as the default root with `BOB_DIR`/`bob_dirs`
  overrides. The parser reads JSON only under `tmp/**/chats/` and tasks from
  `db/bob.db`.

This is parser-side ingestion only. Bob's source database remains read-only;
no AgentsView archive schema or migration changes are planned.

## Generated outputs

Run `make build` in the isolated worktree. Keep the resulting `agentsview`
binary and generated frontend output in that worktree; do not install the
binary.

Generate the full documentation screenshot set with the documented
`docs-generated-assets` workflow. The extractor prepares a privacy-filtered
copy of the local archive before Docker receives it. Keep the generated PNGs in
the isolated worktree and update the local `docs-generated-assets` branch. Do
not push. The current checkout's ignored screenshot directory remains intact.

Use a `sqlite3` CLI compatible with the Go SQLite library that writes the
archive. The test fixture is written by SQLite 3.53.4; the 3.51.0 CLI cannot
open it, while CLI 3.53.4 passes. Put the compatible CLI first on `PATH` for
extractor tests and capture.

## Verification

- Run focused Bob parser tests against JSON and SQLite fixtures.
- Run `go fmt ./...` and `go vet ./...` in the integration worktree.
- Build with `make build` and smoke-run the resulting CLI binary.
- Inspect the generated screenshot set for populated UI, readable controls, and
  private data; run `AGENTSVIEW_DOCS_USE_LOCAL_ASSET_BRANCHES=1 make docs-check`.

## Alternatives considered

- Merging or rebasing the entire current branch onto `v0.46.1` preserves more
  history but spans 2,418 changed files and can restore obsolete fork code over
  upstream changes.
- Building only from `v0.46.1` avoids integration risk but drops the requested
  Bob support.

The isolated Bob-only port preserves the current checkout while keeping the
upstream release baseline clear and reviewable.
